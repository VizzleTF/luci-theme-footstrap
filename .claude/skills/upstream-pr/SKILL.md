# PR в openwrt/luci

Тема живёт в апстриме с 2026-08-20. Код там принимают почти всегда; заворачивают за **форму** —
за дробление коммитов и за длину сообщений.

**Правило поверх всех: коротко.** Медиана тела коммита в openwrt/luci — три строки. Сообщение
говорит, ЧТО поменялось; разжёвывать, почему именно так, не нужно.

## Порядок работы

1. **Ветка.** Переиграть нужные изменения `main` в отдельной worktree, сгруппировать по логике,
   синхронизировать на каждой точке. → `reference/mechanics.md`
2. **Проверки локально.** `npm run check`, их eslint, их правила формальностей, компиляция
   шаблонов, живые стенды. Ловит то, за что иначе прилетит в ревью. → `reference/preflight.md`
3. **Сообщения.** Минимально достаточные, чтобы понять каждое изменение: одно-два предложения.
   Пишутся последними, когда состав коммитов уже не изменится.
4. **Публикация.** `gh pr create`, тело — по строке на коммит, ссылки и `Closes #NNNN` только здесь.
5. **Мониторинг ревью.** Ревью от бота разбираем сами: проверяем каждое замечание, настоящие
   ошибки чиним сразу, треды закрываем. Ревью от человека — уведомление пользователю, разбор
   по существу и вердикт по каждому пункту. → `reference/answering-review.md`

## Сколько коммитов

**Минимально достаточное число, разбитое по логике.** Одно изменение — один коммит; несколько
мелких правок одной области — один коммит на область. Дробить каждую правку в отдельный коммит
не надо, сваливать всё в один — тоже.

Для ориентира: в апстриме медиана — **1 коммит на PR**, 72% пул-реквестов однокоммитные. Наши
двенадцать получили `CHANGES_REQUESTED`, шесть — второй.

## Ориентиры по тексту

| | принято в апстриме |
|---|---|
| тело коммита | медиана **3 строки**, p90 = 15 |
| длина subject | медиана 47 символов, мягкий предел 60, жёсткий 80 |
| ссылки и `#NNNN` в теле | нет у **90%** коммитов |
| перенос строк | 70–72 колонки |

## Жёсткие правила

Каждое оплачено конкретным заворотом.

- **Ни одного `#NNNN` и ни одной ссылки в теле коммита.** Force-push рассылает упоминания заново.
  Ссылка на issue живёт в теле PR.
- **Никакой совместимости с EOL-релизами.** 23.05 отклонён дважды; 24.10 на очереди.
- **Ничего, что нужно только нашим гейтам**: экспорт ради теста помечается `/* fs:probe */`
  и вырезается синком.
- **Никакой саморекламы** — ни ссылок на свой репозиторий, ни имени темы в футере.
- **Никаких миграций «на всякий случай»**: OpenWrt исходит из того, что пользователь обновляет
  образ целиком, а не отдельные пакеты.
- **Комментарий в апстрим-PR пишет пользователь, а не сессия** (`CLAUDE.md`). Ответ сессии — диф
  и resolve треда.
- **`po/` не отправляется** — это Weblate.
- **Никаких AI-трейлеров** в коммитах (`CLAUDE.md`).

## Форма коммита

```
luci-theme-footstrap: lowercase description

Что поменялось. Одно-два предложения, перенос на 72 колонках.

Signed-off-by: Ivan Kvashonkin <vizzlef@gmail.com>
```

Длина тела определяется числом изменений, а не желанием объяснить. Несколько мелких правок
перечисляются скопом, одной строкой каждая:

```
luci-theme-footstrap: fix spacing on luci-base classes

Value rows drew a separator with no row after them, a meter's value sat on
its label in a card, and the per-section Delete touched the tab bar below it.
```

Так — не надо: абзац про то, как выяснили причину, сколько прогонов сделали и почему выбран
именно такой селектор. Это живёт в нашем changelog и в комментариях кода, не в апстрим-коммите.

Subject: префикс пакета, двоеточие, строчная буква, без точки в конце. Для правки общей
инфраструктуры (`luci.mk`) префикс — `treewide:`; `luci.mk:` бот не принимает.

## Что уже отклонено — не предлагать заново

1. **Совместимость с 23.05** — «We are the upstream project. We don't need to keep adding
   compatibility code for old releases just because it happens to be possible».
2. **Ссылка на внешний сайт в футере** — «None of the other themes do that… they are seen as
   originating from the repo itself».
3. **Многословный `uci-defaults`** с чистками старых версий — сокращён со 162 строк до 36.
4. **Публичные экспорты ради наших гейтов.**

## Чек-лист перед `gh pr create`

- [ ] коммитов столько, сколько логических изменений — не больше
- [ ] тело каждого — одно-два предложения, перенос ≤72, без ссылок и `#NNNN`
- [ ] subject ≤60, строчная после двоеточия, без точки
- [ ] `Signed-off-by` во всех, автор — имя и фамилия (`git config user.name` в копии PR)
- [ ] ветка не `master`, имя описывает изменение
- [ ] `npm run check` — 0
- [ ] `/security-review` по финальной ветке — прогнан, находки разобраны
- [ ] их eslint по изменённым файлам — без новых предупреждений
- [ ] вершина ветки совпадает с `main` по шиппящимся файлам и по md5 `cascade.css`
- [ ] в диффе нет `po/`, `Makefile`, наших скриптов сборки
- [ ] тело PR: по строке на коммит, ссылки и `Closes #NNNN` — здесь
